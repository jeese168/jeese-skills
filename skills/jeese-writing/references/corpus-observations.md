# 语料审计记录

这份文件用于以后校准 Skill，不是日常写作指令。初始审计来自作者提供的 12 篇主要技术文档，合计约 33,000 行；第二次校准审读了 5 篇顶层实习整理文档，合计 9,838 个逻辑行，并完全排除明确属于他人的目录。实习材料存在 AI 辅助、面试模板和来源混合，只能用于印证已有模式或发现新的决策边界，不能整篇视为本人原文。

原始语料不随 Skill 分发，也不是运行依赖；本文件只保留后续判断仍需要的聚合观察。结论取跨文档重复出现的模式、用户明确确认的偏好和可以定位的写作选择，不继承问答结构，也不把其中技术事实当成当前权威。

## 稳定观察

- 普通正文约 5,351 段，中位长度约 56 个字符，75 分位约 91，90 分位约 130。
- 97% 以上普通正文使用一个 Markdown 物理行；多数段落只有一到三句，承担一个主要认知任务。
- 高频认知链是：直接定义或结论 → 为什么需要 → 组成或机制 → 具体例子 → 结果、代价和适用条件 → 必要的对比或例外。
- 复杂信息会转入列表、表格、代码或图，而不是堆成长段；但列表通常服务于真实并列、步骤和分类，不替代因果论述。
- 书面说明是主体，口语负责降低抽象度和连接推理。口语是可保留特征，不能因为偶发俚语就整体归类为噪声。
- 术语常以中文名称配英文、缩写或代码标识；例子常展示具体状态变化或故障后果。
- “写得全”通常表现为先补齐业务背景、对象关系和前置条件，再进入实现、异常和代价，而不是把所有相关知识不加筛选地收进文章。
- 技术复盘中反复出现“已实现—实际观测—当前判断—未来改进”的区分；方案选择会考虑当前规模、真实瓶颈、已有基础设施和收益，而不是只比较理论上限。
- 复杂软件流程实际保留了大量 PlantUML 源码并引用渲染后的 SVG，覆盖活动图、时序图、状态图、类图和实体关系图。Mermaid 适合简单图、图片生成用于非结构化定制说明图，是用户本轮明确补充、仍需真实任务校准的选择规则。
- 标题层级以 `# → ### → #### → #####` 为绝对主流：主体长文中有 10 个 H1、75 个 H3、809 个 H4、854 个 H5，H2 仅 3 个且都出现在同一篇跨语言上位分区中，H6 为 0。
- 共识别 107 个表格块、597 个代码块、322 张图片、1,378 行行内代码和 5,023 行加粗；这些格式都有相对稳定的语义职责。
- 6,310 个加粗片段中约 55.7% 不超过 8 个字符，说明加粗主要落在短概念、标签和关键条件，而不是整段。
- 标题后空行比例超过 93%，但大量三行以上连续空行来自面试卡片式分隔，应在文章中归一为一个空行。

## Skill 内保留的校准材料

- [core-style.md](core-style.md) 保存跨样本重复出现、已经进入稳定底座的规则。
- [learning-notes.md](learning-notes.md) 保存学习笔记和技术理解文章的题材规则。
- [markdown-format.md](markdown-format.md) 保存标题、段落、列表、表格、代码和图片的格式判断。
- [examples-and-counterexamples.md](examples-and-counterexamples.md) 保存足以展示关键判断的最小正反例。
- [reality-judgment.md](reality-judgment.md) 保存现实题材中基准率、具体证据、例外和决策权重的判断规则。

重新校准时先检查这些内部材料和真实任务产生的新反馈。只有新证据确实改变判断时，才需要重新访问用户另行提供的外部语料；Skill 本身不能假设那些语料存在。

## 语料中不应机械继承的内容

- 面试题编号、Q/A、追问和面试官口吻；
- STAR、标准答案、面试重点、优势总结和为“完整”生成的固定章节；
- 学习进度标记、星号、来源站点残留、待补充提示；
- AI 对齐链接、内部业务标识、请求数据、账号、令牌、服务地址和代码库私有信息；
- 拼写、编号、标点、版本和硬编码阈值；
- 缺少测量方法、样本范围或彼此冲突的性能数字；
- 缺乏条件的绝对化判断；
- 对话残留、断裂图片和重复粘贴。

“不机械继承”不等于全面消毒。个人文章可以保留有判断力的口语，甚至在语境合适时保留较强烈的表达；Skill 应控制其功能和密度，不能只靠禁词表判断风格。

## 继续迭代的方法

每次用 Skill 完成真实文章后，优先记录用户实际修改过的句段：

1. 用户删掉了哪些结构或解释；
2. 用户把哪些过度书面表达改得更自然；
3. 哪些口语被保留，承担了什么功能；
4. 哪些题材需要独立 profile；
5. 哪些重复错误可以可靠地机械检测。

只有跨文章重复出现的修订偏好才进入 `core-style.md`。单一题材的要求进入对应 profile；可以确定性检查的错误再考虑脚本。
