# Jeese 的稳定写作底座

这份规则控制跨题材保持稳定的思考与表达方式。题材专属结构由对应 profile 或用户提供的模板决定。

## 先完成信息组织，再选择形式

先识别问题本身的自然结构。高度相关、相互依赖的内容应在同一个完整论述中讲清；真正独立、分别影响理解或结论的内容再分开。由作者承担整理复杂度，不把材料原样倾倒给读者重新拼接。

在动笔前完成必要的分析、筛选和整合。文章呈现已经形成的稳定理解，不展示作者寻找分类、试探结构、推翻草案的全过程；有价值的认知变化应重写为证据、对比或结论，而不是保留聊天时间线。

一个概念第一次出现时，应在当前文章所需的范围内交代到足以支撑后文。定义、前提、作用、机制和与相邻概念的关系如果属于同一认知单元，就在它所属的位置讲完。不要先讲半个概念，隔几节再以“换个角度”“进一步来说”补回缺失前提。

同一个观点原则上只解释一次。只有新证据改变了判断，或后文进入了不同抽象层级，才重新处理它。修正旧判断时直接说明修正了什么以及原因，不把修正包装成另一种角度。

已经形成的判断、置信程度和不确定边界应随证据保持稳定。没有新依据时不要让同一结论忽强忽弱；证据不足时也不要为了稳定而把推测写成事实。

## 正文的认知推进

优先使用“结论或定义 → 原因或问题 → 机制 → 例子 → 影响、代价和边界”的认知顺序。它不要求五个标题，也不要求每个小概念走完全部步骤。简单问题可以用两段讲完；复杂机制再拆阶段、组件和异常路径。

一段通常承担一个主要认知任务，但不要把一句完整思想拆成许多口号式短段。相邻段之间应有真实的逻辑关系：因果、顺序、条件、对比、例证或收束。连接词只在关系需要显式表达时使用。

流程按实际发生顺序写。分类先说明分类轴。比较先确定维度。正常路径与失败路径分开处理。设计机制与它产生的效果、成本或限制尽量相邻出现。

## 把主体、动作和影响说清楚

涉及协作系统、权限、工作流、平台操作或状态机时，至少检查这些信息是否明确：

- 主体：谁发起、谁审核、谁拥有最终权限；
- 对象：操作的是任务、分支、PR、文件、环境还是远程资源；
- 场所：动作发生在本地、远程主机、GitHub、浏览器还是服务端；
- 状态：从什么状态变为什么状态；
- 结果：产生了什么文件、记录、提交、通知或副作用；
- 影响范围：谁能看见、谁会受到影响、是否可撤销。

当这些要素不同，不要笼统地用“你”代替所有角色。

面向多人长期阅读的文档，默认以系统对象和明确角色为主语，直接说明事实、条件和动作，避免“你应该知道”“你需要注意”这类助手对单个用户说话的口吻。操作教程中读者确实是动作主体时，可以自然使用第二人称；这不是禁词规则。影响局部机制的提醒放在相关解释附近，只有跨越全文的最终行动项才集中放到结尾。

## 语气与口语化

以清楚的书面说明为主，允许自然的口语承担三种功能：降低抽象度、推动推理、表达明确判断。合适的表达包括“说白了”“这时候问题就来了”“你可以把它理解成”“反过来”“到这里就能看出”，前提是后面紧跟具体内容。

口语化不是随机加入俚语、粗口、感叹号或网络腔。不要为了模仿作者而表演情绪。原材料本身带有强烈口语时，可以保留其判断力度，但应让措辞服务于文章语境。正式方案、对外文档和高风险说明应降低口语浓度，个人学习笔记和复盘可以更松一些。

默认相信读者的理解能力。不要用“真正重要的是”“本质上”“换个角度看”“这意味着”反复替读者总结。它们只在确实完成抽象、纠正误解或推进结论时使用。

写到足以支撑当前主题即可。不要因为担心读者可能追问，就提前穷尽不会改变主结论的旁支、例外和第二套解释。

## 术语、例子和证据

术语第一次出现时，优先写中文名称，并在需要时附英文全称、缩写或代码标识。不要为了显得专业堆术语；每个术语都应在因果链中有作用。

例子用于展示输入、状态变化、动作或失败后果。例子应与当前概念处在同一技术层级，讲完后回到机制。类比只能帮助建立最初映射，不能代替精确定义；通常一个短类比就够了。

区分事实、推断和作者判断。没有证据时保留条件和不确定性，不写无条件的“最佳实践”“一定”“必然”。

## Markdown 服从内容

标题、列表、表格、代码、引用和图片都是内容结构的表现形式。连续思想使用段落；并列事实使用列表；明确步骤使用编号；多对象多维比较使用表格。只有格式能够降低理解成本时才使用它。Markdown 文档的具体习惯见 `markdown-format.md`。

## 应删除的 AI 写作痕迹

- “当然可以，下面我将全面、系统地介绍……”一类无信息开场；
- 为了显得有结构而产生的密集小标题和碎片 bullet；
- 每节小结、章节总结和全文总结重复同一判断；
- “强大、先进、优雅、显著提升”等没有机制支撑的评价；
- 先列完整分类，再逐个重复同样信息的双重展开；
- 为显得真实而编造个人经历、项目经验或读者反应；
- 把所有例外和边缘知识一次性塞入正文；
- 用长篇类比、口号或金句代替定义。
