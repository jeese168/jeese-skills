# 核对正文并写入目标文档

只在最终阶段读取。使用最新有效的草稿、任务要求、依据及组织或设计内容，连续阅读全文或本次受影响的完整上下文。

## 按实际内容修订

- 对照目标与范围，检查整体主线是否稳定，各部分为什么接着出现；相关机制、例子、代价与边界是否在自然位置。
- 检查首次使用的概念是否够用，主体、对象、条件与因果是否明确；读者不需要来回寻找必要前提。
- 检查主体切换、跨段回引处的对象能否就近辨认，回引是否带出当前理解所需的条件；修改或合并后，按调整后的上下文重新核对。
- 对照依据检查事实、设计和判断，保留决定含义的条件，置信程度随证据稳定。
- 检查自然段、列表和标题是否各有作用，合并重复结论，删去无信息过渡与偏离主题的展开。
- 图文、代码、引用与正文一致；计划中的行为未被写成已有能力，验证安排未被写成实际测试通过。
- 使用 [Markdown 指导](markdown-format.md) 检查目标环境所需的标题、链接、图片、代码块与发布清理，项目约定优先。

表达问题直接修订草稿；事实、概念或设计变化更新对应产物及受影响图文。修订后核对相应阶段条件并重跑检查，再继续最终交付。

## 正式写入与实际核对

新文档写入指定新目标；维护更新授权范围；合并写入约定目标。来源文件保持可供回查，文件删除不从合并意图推断。目标已有内容但替换意图不明确时，问清具体冲突；已授权更新的目标直接按范围处理。

写入前核对正式目标和来源是否自准备后发生变化。若已有用户修改，把它纳入当前依据并处理冲突，不能用旧草稿覆盖新的内容。维护优先按实际修改范围更新，整体重组则按已确认范围替换。

写入的是正文和目标所需资产。工作阶段标记留在任务记录；目标目录中的相对链接和图资源应可解析，需要时将正式使用的图源、图片或渲染文件放到项目约定位置。检查实际文件和差异，保护无关修改。

在最终阶段区块记录交付位置、完成的内容、实际核对结果和仍有影响的未决事项。运行本轮最后一个 `--through` 检查后交付可打开的文档链接。只报告实际完成的验证；结构检查不证明文风合格，方案写成不代表项目已经实现。
