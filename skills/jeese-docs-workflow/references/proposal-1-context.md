# 技术方案第一阶段：明确需求与现状

使用当前需求、相关讨论和有效任务记录。读取 [核心风格](core-style.md)、[方案指导](proposals.md)、[依据指导](evidence.md)、[概念解释](concepts.md) 和 [正反例](examples-and-counterexamples.md) 中适用的内容。

## 实际工作与产物

核对本次要解决的问题、预期行为、当前实现和约束。查看相关模块、相邻实现及项目约定，沿实际路径理解职责、协作和关键状态。已有查证仍有效时直接使用。

在产物中形成具体的需求与现状说明，解释后续设计所需的对象、机制、限制及现状与目标之间的差别。保留关键依据、已有决定和需要在设计阶段解决的具体问题；只有用户明确要求诊断实际故障时，才据可取得的现场材料说明当前定位程度。

第一阶段可以留下局部说明草稿，内容聚焦本次需要。对象身份、必要概念、真实条件、因果和判断边界在当前产物中检查，不把需要解释的内容全部推到成文时。

## 完成条件

本次需求与范围、当前行为及关键约束足够明确；现状说明有依据，必要概念可被理解；对第二阶段有影响的设计问题已具体化。尚待选择的改法可以留到下一阶段，不因设计未定而假装已有结论。

落盘后按 [结构检查](artifact-checks.md) 执行 `--flow proposal --through 1`。通过后才读 [方案第二阶段](proposal-2-design.md)。
