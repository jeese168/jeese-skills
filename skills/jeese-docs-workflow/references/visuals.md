# 图与文字一起解释

先确定读者需要从图中看见什么。对象关系、时序、状态、调用、层级和方案差异适合时，主动用图降低理解成本；文字承担定义、原因、作用、条件和判断。图稿在准备内容或组织阶段形成，后续正文实际使用。

## 形式与表达

- 简单关系、流程、状态和时序使用 Mermaid；参与者、消息、分支或标准软件关系较多，Mermaid 布局难读时使用 PlantUML。
- 有适用且可使用的可靠现成图，可以注明来源并说明其与本文的对应。
- 场景、空间或概念组合适合定制说明图时使用可用图片生成工具，核对标签与事实。精确系统关系采用可维护的文本图。

图中对象使用可理解的角色名，准确代码标识供对照。箭头含义、方向和必要条件要明确，实际行为与拟议设计在说明中分清。完整方案可以分别使用现状和设计图，也可以用一张足以说明差异的图，由内容决定。

读图需要的概念放在图前或附近，图外文字解释图难以表达的理由和边界。文字与图各自增加理解，不逐箭头重复。图过载时按有意义的切面拆开，并交代几张图怎样对应。

## 图稿、预览与文档落盘

需要图的阶段，在当前产物区块保留实际 Mermaid、PlantUML 或线条示意代码块及必要说明，并设 `diagram: true`。只写“这里放图”未完成图稿。结构检查只确认代码块存在和非空，关系与表达由 Agent 核对。

图形生成或现成图片也在阶段说明中保留实际文件或来源及其作用；`diagram` 仅标记本阶段承担的文本关系图，不为真实需要的关系图逃避检查。

具备预览或渲染能力时，检查标签、布局、交叉线与阅读顺序；无预览时说明实际检查范围。面向目标文档的阅读环境选择可显示的格式，语法通过不代表已验证展示效果。

图源和渲染文件的位置服从项目约定。阶段内的图稿供回查，正式文档使用其目标目录下可解析的图或相对引用；图资产随文档交付，需要时保留可编辑源码。具体格式沿用 [Markdown 指导](markdown-format.md)。正文、设计或概念修正后同步更新对应图稿与配套说明。
