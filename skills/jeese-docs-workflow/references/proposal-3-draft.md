# 技术方案第三阶段：形成完整方案初稿

使用已确认的本次范围、需求与现状、设计说明、依据、组织安排和图稿。读取 [成文指导](drafting.md)，应用 [方案指导](proposals.md)，按 [产物约定](artifact-checks.md) 取得缺失或修订后的内容。

## 实际工作与产物

按项目结构写出供执行 Agent 或协作者使用的完整方案。需求、现状、改法、作用和理由形成连续论述，必要概念在当前位置解释；实施信息与设计说明相互对应。

图文共同表达关系与过程。方案中的既有行为、拟议变化、成立条件和预期结果保持清楚。验证安排说明怎样观察本次目标是否达到，实际测试结果只使用已经发生的验证。

完整方案初稿放入当前阶段草稿区，独立草稿遵循产物约定。若成文时发现现状或设计问题，更新对应前阶段；涉及重要设计选择时按方案指导与用户讨论。

## 完成条件

读者能理解本次准备实施什么、改法怎样作用、为何这样选择，以及实施和验证需要的信息；各部分组成同一方案，必要前提与图文齐全；正文没有把候选或未来能力写成已确认现状。

落盘后执行 `--flow proposal --through 3`。通过后才读 [方案第四阶段](proposal-4-delivery.md)。
