# 共同准备

结合本次要求和相关上下文确定执行路径、目标文档用途、实际材料、项目约定及落盘位置。任务清楚就继续；只询问会改变本次结果的具体缺口。

## 判断用途和本次范围

学习与项目理解以形成可独立阅读的认识为目标。技术复盘同时区分已实现、实际观测、当前判断和未来改进。技术方案以本次需求和可实施的设计为目标，可以带着需求进入，在设计阶段继续讨论尚未确定的选择。

维护或合并时记录目标是学习说明、技术方案、复盘还是其他项目文档，让对应阶段读取适用指导。文档是长期维护还是临时记录，依据用途、原文和项目上下文选择编辑策略；不设成每次必问项。

本次明确要求决定读者、范围和表达尺度。项目方案通常供执行 Agent 或协作者使用，以本次实施需要确定完整程度，不设置深浅档位。读者信息未明确但不会影响内容时按文档用途处理；不同受众会导致明显不同的背景解释时，问清实际差别。

## 学习文档的抽象层次

先采用用户本次给出的目标或层次；上下文用于给建议，不能因为前面的讲解很深入，就认定文章也要同样深入。未明确时结合当前对象给出具体选项和推荐，等用户选择。

| 层次 | 写到什么程度 | 判断依据 |
| --- | --- | --- |
| 高层：定位与整体关系 | 概念是什么、处于什么环境、解决什么问题、主要对象怎样关联 | 能区分对象，并理解整体作用 |
| 中层：协作与机制 | 沿实际过程说明职责、关键条件、状态变化和结果 | 能连贯解释机制怎样运转 |
| 底层：实现与依据 | 在主问题上对应关键代码、数据、调用、状态或具体实现条件 | 能回到依据核对关键行为和边界 |

例如针对请求重试笔记，可以询问：这次保留“重试与超时的关系”，还是走清一次重试过程，或进一步对照实现看计数、取消和错误处理。层次约束主问题的展开，相邻概念补到支撑理解即可。明确要求改变范围时再调整，不自动逐级扩展。

## 任务目录与正式文档

中间产物位置优先采用用户本次明确指定的位置，否则读取当前 Agent 适用的用户级规则及其明确引用，寻找存放约定。仅查当前平台适用范围。约定明确就使用；路径缺失、冲突或相对基准不明时，具体询问根目录。位置未确定时不擅自选择仓库、Skill 或临时目录落盘。

为新任务建立语义清楚、不冲突的子目录。同一任务的追问和修订沿用目录；同一会话确实换了任务、需要另建目录时，先问用户。默认用 `work.md` 分阶段记录，用户指定名称时沿用。

正式文档路径可以由本次指令或项目约定确定；尚不能确定时在准备阶段询问。新建、维护和合并分别记录目标与来源，避免把任务工作文件当成正式文章。目标已有内容但替换意图不明时问清；明确要求更新指定文档时按范围执行。

用户已指定交付节奏就遵循。默认阶段之间连续推进；只有实际需要用户决定的事项才停下来。阶段落盘和检查不要求每次都请用户批准。

## 留下任务记录

在任务目录留下简短记录：本次要求、执行路径、用途与目标、影响写作的用户偏好、适用项目约定、材料来源、目标路径，以及适用时的学习层次或已确定的实施范围。内容按实际需要组织，记录的是后续必须遵循的信息。

读取 [结构检查约定](artifact-checks.md)，为本轮记录一个 `run`，使用入口给出的 `flow`。默认所有阶段区块留在 `work.md`；阶段首次完成必须有实际落盘动作，之后运行 `--through` 检查。准备记录本身不另算一个写作阶段。

中断恢复先核对本次要求、来源和目标文件是否变化。完整有效内容直接复用；缺失或变化的部分补读，受影响的阶段先修正。仍可用的旧说明能成为新一轮材料，但新一轮各阶段须按当前要求加工、落盘和检查。

准备完成的条件：执行路径、用途、本次范围、必要的学习层次及落盘位置已明确，任务记录可供后续使用。然后返回入口，读取选定路径的第一阶段。
