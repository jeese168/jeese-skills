# 技术方案第二阶段：形成并确认本次设计

使用第一阶段的有效需求、现状、解释与已有决定；缺失内容按 [产物约定](artifact-checks.md) 补读。读取 [方案指导](proposals.md)、[组织指导](organization.md) 和 [图文指导](visuals.md)，解释新增内容时应用 [概念指导](concepts.md)。

## 实际工作与产物

围绕需求和现有实现形成修改方式。说明准备改什么、怎样改、改法怎样起作用，以及选择依据和成立条件。按实际需要写出关键对象、接口、数据、状态、协作及异常行为的变化，递归补齐理解设计所需的前提。

已确认的选择核对适用性后直接采用。重要选择尚未确定时给出具体差异、推荐与依据并询问；部分内容延后或移出本次范围，按方案指导处理。实际设计与未采纳候选分清，正文使用本次已确定内容。

形成可供成文使用的设计说明、关键流程、必要图稿、验证安排及实施边界。图解释关系、时序或状态，文字讲清作用、理由和限制。预期收益、历史原因及项目要求按依据强度表达。

按目标项目结构安排文章内容，连接需求、现状、设计与实施结果，写出关键衔接。各模块分别讲清之外，还要说明它们怎样共同满足本次需求。需要的图在本阶段留下实际图稿。

## 完成条件

本次范围内的关键设计足以支持后续执行；重要选择已明确；新对象和新行为有可用解释；修改方式、作用、理由、条件和验证相互对应；图文与现状及拟议设计一致，正文组织有明确主线。

仍影响本次实施的未决依赖继续处理。事实变化先修正第一阶段；本阶段产物落盘后执行 `--flow proposal --through 2`。通过后才读 [方案第三阶段](proposal-3-draft.md)。
