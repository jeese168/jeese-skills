# 已有文档维护

适用于在已有文档内部新增、移除、改写和重组内容。根据本次用途、原文与项目上下文判断编辑策略：长期文档把新增内容融入自然位置，必要时合并重复和修正衔接；临时记录可以保留日期、追加发现和调查顺序，以可读、可继续处理为目标。

## 延续项目约定并控制范围

检查同目录文档和仓库约定，延续稳定的标题、元数据、术语、链接和排版。单篇文档只有被用户或项目指定为参考时才建立约定；其他情况识别同类文档反复出现的实践。

用户要求统一或提高标准、现有惯例已造成当前问题，或没有可沿用约定时，再采用适合的新结构。必要修改明显超出本次授权范围时，说明具体影响并询问；明确要求重组全文时，按全文范围执行。

## 把增删改作为一次编辑

识别新材料在文中的作用：缺失前提、机制、证据、例子、边界或判断修正。放到第一次真正需要的位置，已有部分覆盖时合并。写出新增解释时就应用 [核心风格](core-style.md) 和 [概念指导](concepts.md)，不是先机械追加再等最终修辞。

移除或改写时，检查受影响的过渡、标题、术语、编号、链接、图与后续结论。只调整表达时保留原有主张；证据或用户意图改变判断时，更新所有直接依赖该判断的内容。

用户可以提供想法、对话、片段或指出不顺的位置；Agent 负责理解意图、寻找归属，并完成为保持一致所需的连带修改。新材料与原文的事实或判断冲突时先核对；无法解决且影响文章时说明冲突及影响，向用户询问。

学习与技术复盘按 [学习笔记指导](learning-notes.md) 判断所需解释；技术方案按 [方案指导](proposals.md) 保持已确认设计与本次范围。早期只留下实际处理过的相关内容和修改关系，原文仍作为来源。

## 验收与交付

长期文档中的新增内容应像原本就属于那里；临时记录中的追加内容应容易定位并继续处理。局部编辑后，相关概念、结论和结构仍然成立。完成后报告重要结构变化、判断变化及未决事项，不逐句复述差异。

一次修改首先是当前任务反馈；只有相同偏好跨文档反复出现，才作为以后校准稳定风格的证据。
