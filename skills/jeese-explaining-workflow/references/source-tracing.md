# 追踪当前要读的源码

仅在源码带读第二阶段读取。先以当前起点、终点和段落范围为界，沿实际实现读取；关注让用户读懂这条路径所需的关系，不收集整个仓库的符号。

## 形成能回查的阅读路径

记录当前文件和符号负责什么、关键输入或状态来自哪里、在什么条件下发生变化、后面由谁使用结果。普通直观的局部操作不逐项记录，关键分支和顺序保留。

跨文件时读取实际定义与相关调用。接口名、类型名和相似实现是定位线索，不是当前调用关系的证明。继承、组合、注册、事件订阅和真实调用分别说明；异步投递不画成同步完成，存在多个实现时核对当前选择依据。

若本次是在理解源码语义，直接解释已查清的代码行为，不因没有日志就反复怀疑每一行是否执行。只有要说明某次具体运行时，才核对相应运行材料；不能将可能经过的代码路径称为该次真实轨迹。

需要返回调用者、走到另一个文件或补框架背景时，记录为什么必须转到那里，以及从哪里接回。对后续代码导航或排查有价值、但当前不必深入的邻近机制，可留下名称、位置和一句职责，不把边缘索引扩成第二条完整阅读主线。

## 在当前位置补足旁支

正文将要使用的陌生对象，先按概念指导写出必要解释。Agent 自己可以多查几个文件，但最终不把查找负担原样交给用户。只有影响本次行为的内部机制才带用户一起跳转。

同一段代码可以在更深层次或另一切面被再次阅读，但应说明这次增加了什么新关系；不要只是重复上一轮的中文翻译。
