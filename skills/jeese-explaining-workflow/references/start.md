# 分阶段讲解的准备

在进入标准、快速或源码带读时读取。准备没有完成，先不要读路线后面的阶段指导或生成终稿。针对性解答不执行这套准备。

## 目的、已有理解与深度

从本轮指令和最近相关对话确认：解释对象、本次用途、要解决的疑问、用户已经建立的理解。材料中出现过某个术语，不代表用户已经理解它；不要把模型自己的前一轮表述当作用户已经掌握的证据。

用户为了某次行动或具体需求了解对象时，用这件事决定哪些背景和机制相关。用户要从零学习整个模块时，相关范围可以更宽。已有信息充分时直接沿用；缺少会改变讲解范围的用途时，针对缺口问，不重述整份问卷。

标准和快速模式还要认清本次是普通学习还是 Bug 诊断讲解，写入任务说明。用户明确在查 QA 问题、解释一次异常或定位根因时选择 Bug 分支；目的已清楚不再让用户选一次。仅有“这个函数为什么返回错误”但无法判断是在读代码语义还是解释实际故障，且会改变查证方法时，针对这个区别询问。

Bug 现场的预期、实际表现、复现条件、版本和日志来源在第一阶段按需要补齐，不要求先填写完整 QA 表。没有日志不是不能开始，也不能把普通源码讲解变成索要运行日志。

模式决定讲解怎样组织，深度决定讲到哪里，两者分别确定。用户用自然语言明确了深度或预期能力，就映射到下列目标并沿用，不要求复述档名。没有指定时，按当前对象给出具体选项和推荐，等用户选择。

| 深度 | 要建立的理解 | 退出依据 |
| --- | --- | --- |
| 定位与作用 | 是什么、处于什么环境、与当前目的有什么关系 | 能区分关键对象，理解为什么本次会碰到它 |
| 协作与机制 | 对象怎样配合、过程怎样发生、为何得到这个结果 | 能沿本次过程说明关键步骤及条件，没有阻断理解的概念缺口 |
| 实现与依据 | 关键行为对应实际调用、状态、数据或实现条件 | 能回到材料或代码核对关键行为，并理解本次涉及的边界 |

把选项说成当前任务里的差别。例如用户正在了解对象重载，可以问：是先弄清重载和旧请求的关系，还是走一遍请求如何被拒绝，或进一步对照实现看版本何时变化。给出推荐理由，不能只丢“浅／中／深”。

不规定递归层数、端数或继承层数。深度作用于本次主问题；相邻对象解释到足以理解其作用即可。若必须超出选定范围才能解释关键现象，说明具体缺口及为什么影响目标，再询问是否深入。已知背景足够时不重复追溯。

## 确定中间产物根目录

1. 优先沿用用户为本次任务明确给出的位置。否则查看当前环境已提供或可定位的、适用于当前 Agent 的用户级规则，寻找中间产物的存放约定，例如用户级 `AGENTS.md`、`CLAUDE.md` 或 Cursor 用户规则。
2. 只查看当前平台适用的规则及其明确引用的位置；不遍历所有平台配置，不扫描整个主目录，不假设不同平台使用相同路径。规则已经在上下文且约定明确时，不重复寻找。
3. 没有约定、规则无法访问、多个目录冲突，或相对路径的基准不明时，说明实际缺口并询问根目录。用户可以直接提供本次位置，也可以先补充用户规则；选择后者时，重新读取确认。不要擅自写入用户配置，也不要把“没有访问到”说成“规则不存在”。

根目录是运行时输入，不写死在 Skill 中。用户已有的自然语言约定有效，不要求先创造某个固定配置键。目录确定之前，不在仓库、Skill 目录或临时目录中擅自回退落盘。

## 按任务建目录并留下任务说明

根目录确定后，为新任务创建语义清楚、避免冲突的子目录，名称由 Agent 根据本次对象自行决定。不把多个任务的文件直接堆在根目录，不覆盖同名旧产物。路径访问和写入仍服从当前环境的权限。

同一会话已有任务目录时，先判断是不是继续同一件事。相同对象的追问、修正或用户要求换模式，通常可以沿用。若判断已经换任务、需要另建目录，先问用户是否新建：同意才自行命名新目录，不同意就在原目录内分清本次内容。不要把每次阶段切换都当成换任务，也不要只因窗口没变就把不同任务混在一起。

默认在任务目录内使用一份 `work.md` 分节记录。文件名只是本 Skill 的默认值；用户另有命名约定时沿用。留下简短的任务说明：对象和用途、模式和深度、适用时的普通／Bug 分支、已知理解与当前疑问、材料来源、当前阶段。只记录影响后续生成的信息，不复制聊天记录，不填无意义的空字段。

此时读取 [artifact-checks.md](artifact-checks.md)，在任务说明中记录本次 `run` 标识；后续各阶段按其约定包住实际内容并运行检查。只固定外围标记，不固定正文标题和表格。

阶段产物可在同一文件内增补或修订；图的 PlantUML、Mermaid 或线条文字示意直接保留在相应阶段的代码块中，不要求独立图文件。续做时确保所需最新记录可用，按 [补读约定](artifact-checks.md#按需取得中间产物) 取得缺失或变化的部分，不把整份历史重新装入上下文。模式切换沿用仍有效的依据，在文件内明确本次模式及新增的阶段内容；不把上一模式的完成状态直接当作新模式也已完成。

中断恢复时核对本次对象、用户要求和材料是否变化。只有相应产物仍有效，才从已完成阶段继续。事实被修正后，旧的图和组织安排不能继续标为有效。

## 准备完成的条件

模式、目的、深度和落盘位置已足够明确，任务说明已经写入。多个缺口可以一次简明询问；只有真正缺失的答案需要等待，不重复索取已确定的信息。

此时返回入口，读取选定路线。源码带读还会在第一阶段确认阅读范围和交付节奏。阶段产物用于后续生成，最终讲解默认交付在对话中；用户另有文件交付要求时按要求执行。
