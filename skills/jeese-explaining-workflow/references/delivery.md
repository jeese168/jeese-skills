# 生成并核对最终讲解

只在标准或源码带读第四阶段、快速第三阶段读取。先读取当前有效的阶段产物，按已经形成的组织安排完成回答；不从空白重新生成一套与前面无关的内容，也不把 `work.md` 逐节复制给用户。

## 连续、自然地讲清楚

先回应用户实际问题。紧密依赖的内容连在一起，概念首次出现时已经足以支撑后文；建立后沿用，不重复解释。补足理解需要的对象、关系或位置即可，不把每个概念写成固定坐标表。

使用自然的中文名称和准确标识。先说清具体文件、对象或规则，再解释它的位置和作用；“这一层”“后面那段”不能代替对象身份。措辞可以自然口语化，不表演情绪，不堆抽象近义词。

连续思想用段落，真正并列的事项用列表，实际步骤用顺序，比较多个维度时用表格。必要的标题直接指出对象和本节结论，避免装饰性标题、宽泛问题标题和结尾再重复一次全文。

机制和它解决的问题、产生的后果尽量相邻。代码只展示支撑理解的必要片段，先说明它要证明什么，再指出关键条件或行为；不拿代码块代替解释。图和文字按既定阅读顺序配合，核心概念不能只在中间附录里。

标准模式以文字承载充分解释，图用于确实更清楚的部分。快速模式缩小展开范围、减少重复，让直观呈现和必要文字共同建立认识；不把完整性理解为列出对象的全部能力。

源码带读保留说明对应的实际阅读位置和必要跳转，按已确认的一次交付或分段节奏进行。Bug 分支明确当前诊断能支持到什么程度；需要建议时分清表现、原因和候选修改位置，工程取舍由用户决定，不能把中间产物审查的两类处置当作已经批准工程方案。

对照：反例是“这一层处理完后到下一层”，没有说明对象。正例应使用实际符号和文件指出当前处理在哪里完成、下一处负责什么。标题也应压缩具体对象及本段结论，不用“后面怎么配合”这样的模糊关系当标题。

## 交付前核对实际内容

对照本次问题和深度检查，而不是仅宣布“已检查”：

- 所问内容都得到回答，结论没有超出已有依据；有实际影响的未知仍然可见。
- 首次使用的关键概念有足够解释，跨层补充没有打断主线或无限展开。
- 过程、条件和图中关系与查证结果一致，必要前提没有被压缩掉。
- 图、例子和正文各自增加理解，没有重复功能清单、反复总结或形式化填表。
- 项目特定判断保留可回查来源，引用没有丢失条件，验证只报告实际做过的内容。

表达问题就地修订；事实或概念发生变化时，返回对应阶段并更新受影响的产物。不要为了让终稿流畅抹去代码、运行证据或验证范围中的真实限制。

## 完成与后续

按路线要求更新 `work.md` 的实际状态。分段带读保存停点，有限 Bug 定位保留未完成的调查；不要一律标为整个任务完成。默认在对话中交付可直接阅读的本次说明，必要时附中间产物和图的可用链接，遵循当前平台的文件链接约定。中间文件是可检查的工作材料，不要求用户先读它们才能理解答案。

用户另有保存终稿的要求时按指定位置执行。后续追问沿用已建立的理解，只修补所问部分；模式切换由用户决定，不自动布置下一轮学习。用户之后要整理成长期文档时，按新的文档请求组织，不把本次查证或聊天过程当成文章结构。
