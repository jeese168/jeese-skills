# 在最终讲解前调用可选独立审查

只有用户明确要求子 Agent 检查本次中间产物时读取。调用时点是标准或源码带读第三阶段、快速第二阶段完成之后；没有要求就继续正常路线，不主动询问是否增加审查。

## 交给 jeese-engineers 情况六

通过当前环境提供的 Skill 清单、技能发现能力或用户指定的位置定位 `jeese-engineers`，读取其入口并进入情况六及其指定的 reference。不要写死本机安装路径，不从本 Skill 用跨目录相对链接读取另一份源码，不假定任意版本都有情况六。

向情况六明确交接用户已经提出的独立审查要求，以及本次目的、模式、深度、已有理解、最新 `work.md`、图及必要依据的位置。指出当前阶段和完成后要返回的下一阶段。复用已有任务目录，不重问根目录，不重新选模式。

Bug 分支交代当前是已定位根因、有限定位还是待验证；检查材料能否支持这个程度的诊断，不让审查方替用户决定工程修改归属。源码带读交代本次阅读范围和已完成位置，分段模式只审本次要交付的材料，不把同一批产物随每个追问重复送审。审查范围沿用用户要求：只要求审本段，就不自动扩展到后续段；明确要求每段都审，就在各段对应检查点执行，不反复询问授权。

情况六负责实际派出子 Agent、由主 Agent 核实发现并分为采纳／不采纳、直接修正中间产物。不要改用情况二的手动送审，也不要把结果交给情况四再等待用户拍板。

## 返回与限制

情况六完成后，使用最新产物及处置记录，按 [补读约定](artifact-checks.md#按需取得中间产物) 取得当前上下文缺失的修订内容，确认当前阶段退出条件仍然成立；有产物修订时仍必须重跑当前结构检查点，再读最终交付指导。独立审查只覆盖实际交接的中间产物，不代表尚未生成的最终讲解已被子 Agent 检查；终稿仍按本模式自检。

Skill 不可用、缺少情况六或没有可用子 Agent 能力时，说明具体限制，不自动安装或改写其他 Skill。审查调用失败或没有有效结果时，保留产物并停在检查点，不把主 Agent 自检写成独立审查。用户明确撤销本次独立审查要求后，才继续不带审查的路线。
