# 中间产物的结构检查

在落盘准备时读取一次，后续按当前检查点执行。[检查脚本](../scripts/check_artifacts.py) 使用 Python 3 标准库，不安装依赖，不扫描用户配置或整个根目录，只读取传入的任务目录内指定 Markdown。路径仍按 [start.md](start.md) 确定。

## 在自由正文外加阶段标记

任务说明继续自然书写，同时记录本次使用的 `run`。每阶段实际产物放在下面的一对独立行标记之间，JSON 只占一行。区块内按实际内容选择标题、段落、列表或表格，篇幅以支撑后续使用为准。

````markdown
<!-- workflow:{"run":"cache-quick-1","mode":"quick","branch":"learning","stage":1,"diagram":false} -->
## 本次需要理解的缓存行为

已核实的实现先读本地缓存，只有缓存缺失或失效才访问远端。
缓存失效表示本地结果不能继续满足本次读取条件，不等于每次都没有缓存。
<!-- /workflow -->
````

例子仅演示格式，不是项目事实。五个字段都必需：

- `run`：这一轮模式执行的标识，由 Agent 自行命名；同一轮各阶段一致。换模式、开始新一轮或源码带读新一段时用新标识，不用旧产物冒充新产物。这不要求另建任务目录。
- `mode`：`standard`、`quick` 或 `source`，分别对应标准、快速了解和源码带读。
- `branch`：`learning` 或 `bug`；源码带读固定用 `learning`，保持它自己的路线。
- `stage`：本模式阶段编号。标准和源码带读为 1–4，快速为 1–3。
- `diagram`：本阶段需要保留图示时为 `true`，否则为 `false`。按实际呈现决定，不能为了通过检查改成 `false`。

同一 `run` 的同一阶段只保留一个有效区块；修订时就地更新，不追加重复版本。标记只用于阶段产物，不为每个概念或每个小标题加标记。任务说明和补充记录可以在区块之外，但不能用区块外的内容代替应在本阶段写出的产物。

## 图示放在阶段正文的代码块中

使用图的阶段，在该阶段区块内保留实际的围栏代码块：PlantUML 用 `plantuml`，Mermaid 用 `mermaid`，线条与文字组成的示意用 `text` 或 `ascii`。例如：

````markdown
<!-- workflow:{"run":"cache-quick-1","mode":"quick","branch":"learning","stage":2,"diagram":true} -->
先说明正常读取，再说明访问远端的条件：

```text
读取请求 ──> 本地缓存 ──命中有效结果──> 返回
                 └──缺失或失效──> 远端
```

这张示意只表达读取关系；失效的具体条件由前阶段核实的实现说明。
<!-- /workflow -->
````

阶段需要图时，在正文区块内至少保留一个上述类型的非空图代码块，各图块写入实际图稿及必要说明。多张图按理解需要保留；脚本检查图块是否存在、非空，PlantUML／Mermaid 语义、渲染效果及 `text` 块是否表达了实际关系仍由主 Agent 核对。普通源码代码块不会自动算成图。

## 每阶段落盘后运行

用当前环境定位到的 Skill 源目录替换脚本位置，给任务目录、文件名等参数正确加引号。以下是假设目录的命令示意，不能直接当作本机路径：

```sh
python3 "<Skill目录>/scripts/check_artifacts.py" \
  --task-dir "<已确定的任务子目录>" --file "work.md" \
  --run "cache-quick-1" --mode quick --branch learning --through 2
```

`--file` 默认是 `work.md`；用户指定其他名称时传入任务目录内的相对路径。`--through` 是已经完成的当前阶段，只检查该轮从第一阶段到这里的产物，不要求未来阶段已经写出。命令中的模式、分支和 `run` 以本次任务为准，脚本与文件标记相互核对，不自动挑一个已有的完整旧轮次。

每阶段写完并完成内容自检后都必须运行，包括产物刚生成、完整内容仍在当前上下文中的情况。脚本从磁盘检查，不要求模型为此重读全文。标准第三阶段／快速第二阶段／源码带读第三阶段检查通过后，才进入可选独立审查或最终生成。最后阶段写入本次交付内容的简要说明和实际任务状态后也检查。完整讲解默认在对话中交付，已有图稿保留在其所属阶段。最后阶段仅记录交付及状态时，`diagram` 为 `false`；实际包含图示产物时，按图示规则写入代码块并设为 `true`。

- 返回 `0`：结构检查通过。只能这样记录，不能说“内容合格”“审查通过”或“已证明按顺序执行”。
- 返回 `1`：标记、缺阶段、空区块或声明的图代码块有问题。按具体报错修正产物并重新运行，不靠删除要求跳过问题。
- 返回 `2` 或命令无法运行：参数、路径、读取或运行环境有问题。核对实际原因；无法解决时说明检查未完成，不静默跳过，不自行安装运行环境。

文件中的阶段标记须成对、JSON 有效；代码围栏里的格式示例不作为实际阶段。正文非空检查排除标题、注释、分隔线和空代码块，不按业务关键词、最低字数或表格模板打分。脚本不检查概念是否充分、事实是否正确，也不能证明前阶段被实际读取。

## 按需取得中间产物

中间产物必须落盘，供后续引用、恢复、核对和修正；降低重复读取不改变这一要求。下一阶段使用实际写出的概念、关系和图稿，不把它们缩成“已检查”或过度压缩的摘要。

先判断本阶段需要哪些产物：完整且有效的内容仍在当前上下文中就直接使用，不再调用工具输出同一份正文。内容缺失、输出被截断、压缩后只剩摘要，或磁盘修订的最新内容不在上下文中时，才补读相关区块。是否跨过一轮对话不是判定条件；无法确认版本是否有效时，核对并补读受影响区块，不凭模糊记忆继续。

用同一脚本的读取参数提取本轮指定阶段，例如只需要第二、三阶段时：

```sh
python3 "<Skill目录>/scripts/check_artifacts.py" \
  --task-dir "<已确定的任务子目录>" --file "work.md" \
  --run "cache-standard-1" --mode standard --branch learning --read-stages 2 3
```

脚本只输出指定区块的标记和完整正文，不输出其他阶段、旧轮次或区块外材料，也不生成摘要。缺少目标阶段、标记无效或轮次身份冲突时返回错误，不退回输出全文。任务说明、停点等仍在区块外的必要记录，按已知标题或位置另行小范围读取。

`--read-stages` 与 `--through` 是两个独立用途，不能在一次调用中混用：前者补读内容，不检查前置阶段是否齐全或正文是否非空，也不打印“结构检查通过”；后者进行每阶段必需的磁盘校验，只返回通过或报错。补读成功、上下文中已有内容，都不能替代 `--through`。

不把整份 `work.md` 当作每阶段的固定开场。当前阶段确实需要多份产物时可以一起补读；选取范围由实际依赖决定，不固定为“只读上一阶段”，也不为节省上下文删掉必要解释或图稿。这里仅约束中间产物的读取，不改变各阶段首次加载指导文件的顺序。

## 续段、追问与修正

源码带读续段使用新的 `run`。先沿用仍有效的范围记录，更新本段起止位置，作为新一段的第一阶段区块，然后从第二阶段接着准备。这只是复用并更新范围记录，不重新询问目录、深度或已经确认的阅读目标；旧段的第二至四阶段不能填充新段。

针对性解答仍不强制落盘、不要求新建标记。若纠错需要修订已有的带标记产物，保持原 `run` 和阶段，更新受影响的正文及图；按当前有效检查点重跑脚本。对于尚未带标记的旧任务，不为一次追问补造全部历史阶段；真正恢复分阶段路线时，核实后为本次要复用的有效内容加标记，再检查。

独立审查或事实修正改动了产物时，也重跑当前检查点；结构检查不替代相应的内容自检和上游修正。源材料已变而文字仍非空，脚本也可能通过，这种失效仍由 Agent 查证。
