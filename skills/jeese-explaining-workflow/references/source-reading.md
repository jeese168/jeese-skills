# 源码带读：四阶段

用于用户要边读说明、边对照源码的任务。以实际阅读位置和理解顺序组织，不是标准讲解加上更多代码块，也不逐行翻译语法。已完成入口准备后执行。

每阶段实际内容写入本次 `run` 的对应标记区块，落盘和内容自检后运行 [结构检查](artifact-checks.md)，`--mode source --branch learning`，`--through` 使用当前阶段号。分段带读每段使用新 `run`；通过后才进入下一阶段。

## 第一阶段：确定阅读起点和范围

使用当前有效的任务说明，缺失时补读相应记录，并读取 [evidence.md](evidence.md)。根据当前请求提供必要选择，已有答案就沿用：

- **从哪里开始**：指定文件、函数或类；从某个功能的入口顺着执行过程；沿某个对象的创建、使用和销毁。
- **读到哪里**：本次要看懂的行为或路径终点。用户没有给出时，先核对相关入口，提出一个可实际走通的范围供确认，不默认遍历整个模块。
- **怎样推进**：一次交付约定范围的伴读说明，或分段交付、由用户说继续后再往下。节奏不明时给出推荐并询问，不把分段变成固定课程。

深度沿用用户在准备阶段明确作出的选择。必要旁支由 Agent 先查明，再在当前位置解释职责；只有旁支内部行为影响主线时才深入。

核对起点确实存在，将起点、终点、深度、节奏和可取得的代码版本或文件状态写入 `work.md`。不要为无版本管理的材料编造提交号。

**可以继续时：** 读什么、从哪里走、读到哪里及交付节奏已经明确。分段模式只确定整体方向和当前段边界，不提前读取完整仓库。此时才进入第二阶段。

## 第二阶段：追踪源码并补齐必要概念

使用当前段的有效范围记录，只按 [补读约定](artifact-checks.md#按需取得中间产物) 取得缺失或变化的区块，再读 [source-tracing.md](source-tracing.md) 和 [concepts.md](concepts.md)。实际追踪当前范围或当前段的代码，形成可回查的阅读路径；核对必要的跨文件引用、异步边界和状态变化，写出理解它们需要的说明。

产物写入 `work.md`：实际文件、符号和位置，路径之间为什么相连，必要概念和旁支职责，以及尚未核实的连接。分段模式可留下后续待读位置，但不得把未读部分标为已核实。

**可以继续时：** 当前段的关键行为与跳转有依据，必要概念已经讲明，能对照源码阅读；无法确认的连接没有被画成确定调用链。材料缺失导致主线走不通时补查或说明具体缺口。

## 第三阶段：编排伴读说明

使用当前段的有效路径与实际概念说明，只补读缺失或变化的区块，再读 [organization.md](organization.md) 和 [reading-presentation.md](reading-presentation.md)。需要图时再读 [visuals.md](visuals.md)。

把解释对应到实际阅读位置，写出本段具体的伴读草稿和必要图文，补充关键跳转的理由。需要图时在本阶段区块保留图代码块并标记 `diagram: true`。用户只需打开主线代码，旁支的必要知识在说明里已经够用；不把“请自行阅读相关类”当作解释。

**可以继续时：** 说明与源码位置一致，用户知道当前看哪里、这段完成什么、下一处为什么相关；必要定义没有藏在附录，草稿不是只有文件清单。用户要求独立审查时读 [review.md](review.md)，完成本次范围的检查后再进入第四阶段。

## 第四阶段：交付并保存阅读位置

确保当前段的最新草稿及必要依据可用，只补读缺失或变化的区块，再读 [delivery.md](delivery.md)。交付可直接对照代码的说明，核对位置、符号、语义、图和引用。代码版本已变化时先核对受影响的路径，不沿用失效位置。

一次交付模式完成约定范围后记录完成。分段模式只交付本段，在 `work.md` 记录最后读到的文件和符号、已讲明的关键关系、下一段起点及尚未覆盖的范围，然后等待用户继续。不能把“本段完成”写成“整个任务完成”，也不要自动把后续段落连着发完。

局部追问使用 [focused.md](focused.md)，保留阅读位置。用户说继续时，取得有效的范围和停点记录，只补读缺失或变化的部分，并核对相关代码是否变化；新段用新 `run`，复用仍有效的范围说明并更新本段边界，记入新段第一阶段区块、检查后，从第二阶段接着准备，不重问已确定的目录、模式或深度。用户调整目标或范围时先更新第一阶段记录，再继续。
