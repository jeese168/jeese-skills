# 确定范围和解释深度

用于标准、快速和源码带读。深度决定主问题讲到哪里，讲解情况决定怎样组织，两者分开。以用户对本次问题明确提出的深度或预期能力为准；用户用自然语言说明想理解到哪里即可，不要求复述档名。只指定“标准”或“快速”，不等于已经选择深度。

用户没有明确深度或预期能力时，结合当前对象给出简短的具体选项和推荐，等待用户选择后再展开讲解。上下文可帮助理解对象、用途和形成推荐，但不能根据前文的篇幅、技术层级、术语或 Agent 自己讲过的内容替用户选档，也不能假定用户已经读过或理解那些内容。

同一次讲解或分段带读中，用户已经明确选择且未调整的深度可以沿用，不重复询问。换了问题不能仅因话题相近就继承旧档位；用户明确要求沿用时再沿用。多个真正缺失的问题可以合并询问。

| 深度 | 要建立的理解 | 如何判断已经够用 |
| --- | --- | --- |
| 定位与作用 | 是什么、处于什么环境、与当前目的有什么关系 | 能区分关键对象，理解本次为什么会碰到它 |
| 协作与机制 | 对象怎样配合，过程怎样发生，为什么得到这个结果 | 能沿本次过程说明关键步骤及条件 |
| 实现与依据 | 关键行为对应实际调用、状态、数据和实现条件 | 能回到材料核对关键行为及本次涉及的边界 |

例如对象重载：先弄清重载与旧请求的关系，走一遍旧请求怎样被拒绝，或进一步对照实现看版本何时变化。推荐要说明与本次目的的联系，不只丢“浅／中／深”。这些是通用理解目标，不按客户端、服务器、继承层数或具体框架硬编码。

主问题达到所选深度，相邻对象补到足以理解作用即可。材料中出现过某术语、模型以前提过它，不代表用户已经理解。到已有基础或足以完成本次理解的位置停止递归；不能以快速为由删去关键前提，也不能为了没有任何未知无限追溯。必须显著超出约定范围时说明原因并询问。

针对性解答不执行深度问卷；现实判断按问题与证据展开，不套源码深度档。
