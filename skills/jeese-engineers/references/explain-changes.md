# 讲已经改了什么

对照少样本：[只问一点时只答那一点](examples-and-counterexamples.md#只问一点时只答那一点)、[讲全并指定重点时完整回答](examples-and-counterexamples.md#讲全并指定重点时完整回答)、[沉淀时按实际改动把相关部分讲全](examples-and-counterexamples.md#沉淀时按实际改动把相关部分讲全)。

这一情况出现在中间或更晚。先看用户这一句要的是哪一种深度，再开口。

## 只问某一个点

用户问的是某一处行为、某一个文件、某一个函数、某一次失败为什么这样改。把这一点讲清楚：改前做什么、改后做什么、依据是什么。讲到用户能接着读代码、或接着问下一句为止。

问的是点，答的也是点。这一轮的产物就是这一个问题的答案。

## 要做笔记、归纳、沉淀，或要求讲全

用户明确要整理、归纳、沉淀，或要求把相关改动讲完整时，按磁盘上的实际改动组织说明。每一处改动写清：文件和对象、改前行为、改后行为、影响谁、用什么证据支持。

当前结果以磁盘上的实际文件为准。还原「改前」时，使用能对应本次任务的差异、版本记录、用户提供的原文或可靠的任务记录，并说明实际来源。Git 状态、P4 已打开文件用于定位候选对象；工作区差异可能混有此前修改，需要先核对任务归属。无法恢复准确原文时，说明缺口，只讲已核实的当前结果和能够确定的变化。

大段新增能力按模块或可观察行为分组，点出入口和对外可见结果。精确小改动把决定含义的前后片段放在同一段说明里。

## 两种深度怎么认

用户点名一个对象、一个现象、一句「这里为什么」：走「只问某一个点」。

用户说要沉淀、做笔记、归纳、把这次改动讲全、或要一份以后还能用来写文档的说明：走「讲全」。

用户明确要求讲全，同时点出重点时，完成整体说明，并在指定部分投入更多解释。用户只是说明将来要做笔记、当前仍只问一个点时，回答当前问题。按本次实际要求确定范围和篇幅。
