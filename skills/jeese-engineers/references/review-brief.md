# 为当前方案或改动生成完整送审指令

对照少样本：[审查指令客观并写清本轮怎么审](examples-and-counterexamples.md#审查指令客观并写清本轮怎么审)、[生成的指令带齐审查和回复要求](examples-and-counterexamples.md#生成的指令带齐审查和回复要求)、[增量审查指令交代文件内部的比较范围](examples-and-counterexamples.md#增量审查指令交代文件内部的比较范围)、[送审与独立核查按用户要的产物区分](examples-and-counterexamples.md#送审与独立核查按用户要的产物区分)。

## 时机和产物

用户在改完、输出完之后点名，包括情况一的路径已经整理完之后再点名。这一轮只生成审查指令，直接打在对话里。

这份指令是给**另一个窗口里的审查 Agent** 用的，针对当前方案或改动生成。用户会把它和原始材料或路径清单拼在一起。指令写完，这一轮就结束。

生成前读取 [references/review-findings.md](review-findings.md)，按当前对象选取判断标准、证据要求和发现的组织方式，将审查方执行本次任务所需的内容完整写进指令。这是主 Agent 的编写过程；交付文本直接面向审查方，说明其要检查的内容和要返回的发现。

## 指令里应写清的内容

按当前任务当场写，写成本轮能直接粘贴使用的说明，包含：

1. **被审对象会以哪种形式出现。** 用户可能把窗口里直接打出的技术方案用固定格式包成「引用的原始材料」；也可能把情况一列出的绝对路径和路径说明包在一起。两种都要能审。对象是用户贴来的材料或路径指向的文件，以那份材料为准。
2. **本轮审查范围。** 用户已经选定增量或全量的，把这个范围及对应任务写进指令。增量按下节交代可核对的比较范围；全量审这些路径所覆盖的、与当前功能相关的全部已落盘内容。用户在材料里另有更窄指定的，以用户指定为准。
3. **审查所需的背景与判断依据。** 把影响本次判断的最小必要背景直接写进指令：要解决的需求、用户已确认的前提、约束和预期行为、已确认可行的协作条件，以及当前交付范围、后续阶段安排和待定事项。尚未确认的协作安排单独标为待定，说明其成立条件。将执行 Agent 自己选择的实现做法标为待审选择，并给出可核对的依据。另一个窗口应能凭这份指令和用户拼接的材料理解任务；需要补充阅读时，指出具体来源。判断标准按当前对象选择，包括用户已确认的意图、真实文件、方案的一致性和可行性。

   技术方案或工程变更的送审指令，应按当前任务写入 [review-findings.md 的判断尺度](review-findings.md#按当前任务决定意见与修正)：结合已说明前提审查实际方案；新增区分或提前讨论后续事项时，说明它对本轮决定的实质影响；提出配套机制前，先判断风险前提是否必要，并考虑已确认的协作条件和足够的最小修正。未确认的协作安排作为有条件的建议，不作为已成立的保证。具体措辞随任务调整。
4. **与相关实现怎样配合。** 按本次变更的实际影响，指出应核对的框架约定、调用方、数据来源、执行顺序、配置或关联模块。未修改的相关文件也可以作为证据；检查应围绕本次任务及其影响展开。
5. **结论怎么写。** 将适用的发现组织和证据要求写入指令：默认用简体中文逐项交代具体位置、问题的依据、影响和建议；区分已确认问题与尚未验证的风险；说明实际验证及其限制。没有确认问题时，说明审查范围和依据。根据本次对象选取必要要求，将相互依赖的背景、检查条件和报告要求连贯组织。
6. **这一窗口的职责。** 读取送审对象及必要依据，在对话里报告发现，保留被审文件原状。

这些是生成指令所需的信息，按任务合并组织。交付时检查另一个窗口能否仅凭指令和用户将附上的对象理解任务：关键上下文、比较范围、审查要求和回复方式都应可见。

## 增量审查需要可核对的比较范围

文件路径确定审查对象，比较范围确定对象里哪些变化属于这次任务。按实际证据交代修改前后对应关系，可以使用已确认的提交范围、任务对应的 diff、相关符号及其具体变化、或可靠的修改前材料。所选来源应能让另一个窗口找到并核对本次变化；来自对话的必要信息应在指令中带过去。

Git 工作区差异、P4 已打开文件或变更列表可能包含多次任务的累积修改。先核对任务归属，再描述本次增量。审查相关调用链和相邻代码可用于验证这些变化，发现范围仍以用户指定为准。

证据不足以恢复准确边界时，写明已确认的部分和缺失的比较材料，并说明哪些结论暂时无法验证；边界缺失导致本次增量审查无法开展时，针对缺失范围向用户询问。用户选择全量后，再按全量生成指令。

## 客观

指令站在审查方，按材料和文件能否核实来写。执行窗口自己做过的选择，写成审查方需要核对是否成立的对象，并指出可以核对的材料位置。

当前任务里仍不确定、需要产品或他人拍板的点，在指令里标明为待核对项，让审查窗口看见边界。
