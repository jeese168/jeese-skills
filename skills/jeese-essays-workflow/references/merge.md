# 多篇文章合并

用于把明确选定的多篇文章或章节合成一篇。完整读取本路线，结合核心风格执行三个阶段；每阶段按 [产物与检查](artifacts.md) 落盘并核对后继续。

## 第一阶段：读懂各篇，形成合并主线

使用本次要求和指定来源，完整阅读要合并的文章；只合并选定章节时读取明确范围，并补足理解其判断需要的上下文。记录来源位置及当前状态，了解每篇的由来、主张、理由、例子、叙述视角和表达力度。

根据本次目的确定合并后要说清什么。用户指定一篇为基础时，以它承载主线，判断其他内容怎样补入；要求重新成篇时，根据各篇内容形成统一推进。标题、引子、关键原句和比喻的取舍服从这一主线。

| 来源之间的关系 | 处理与本阶段产物 |
| --- | --- |
| 同一判断反复出现 | 选取更准确、有表现力的表述，留下各篇独有的理由或例子及其归属 |
| 各篇解释不同侧面 | 写清互补关系和必要前提，整理出可以共同支撑的意思 |
| 同一现象因对象或条件不同得出不同判断 | 交代差异所依据的条件，确定各自在合并文章中的位置 |
| 认识随时间变化 | 按本次目的保留演变过程或采用用户已明确的当前认识，保留决定含义的时间关系 |
| 结论或立场确有冲突 | 核对来源与本次要求；仍会改变作者主张时，列出具体分歧及影响后询问 |

批判和自省出现在不同来源时，依据各自作用组织语气变化。原文强烈的判断和比喻要连同支持它的理由一起考虑，保留用户希望表达的锋芒或留白。

产物保存：合并文章的由来与主线、已处理的关键意思、来源对应、重要原句及取舍理由、各部分的内容关系。前期完成来源判断与内容整理，完整文章在第三阶段形成。

完成条件：各来源的重要意思都有明确去向，重复与互补已经处理，影响主张的冲突已解决，整体安排对应具体内容并体现本次表达倾向。

落盘并运行 `--through 1`，内容条件与结构检查都通过后进入第二阶段。

## 第二阶段：融合论述，写通来源之间的关系

使用第一阶段的主线、取舍、加工后的内容与必要来源，把原本分散的解释、例子和判断写成能够连续阅读的论述。共同前提放到适当位置；概念在合并后的首次使用处解释，指代的对象与条件保持明确。

写出各来源之间真正需要的过渡，让读者知道为什么从这部分进入下一部分。保留的比喻、模拟话语和强句放在论述支撑它的位置；认识变化沿过程推进，直接批判落到对应行为和关系。

例如一篇讨论“给予之后形成心理账本”，另一篇讨论“冲突时拿旧事索取解释权”，可以先讲期待怎样形成，再讲期待怎样进入争执，并写出两者之间的联系。这种组织需要来源实际支持，不能仅因题材接近就认定存在因果。

产物保存融合后的关键论述、来源之间的实际衔接，以及适用的标题与结尾落点。对照第一阶段确认独有内容、条件和判断仍在；原意或取舍变化时更新第一阶段。

涉及配图时读取入口的配图指导，按新文章的论述位置处理图位、FIG 与提示词。已有图注沿用或调整到对应意思，新增提示词进入任务目录的 `illustrations.md`。

完成条件：主要内容已融合成可用论述，概念与关键过渡充分；来源中的重要条件、表达力度和认识变化得到保留；图文安排能够进入成稿。

落盘并运行 `--through 2`，两项检查通过后进入第三阶段。

## 第三阶段：形成全文，对照来源核对

使用最新融合论述与来源取舍，形成完整合并稿，完成引子、全文衔接、重复取舍和结尾，随即核对修订。

先对照来源及第一阶段的安排，检查重要主张、理由、例子和成立条件是否得到处理；再连续通读，检查各部分是否沿同一主线推进、不同语气的转换是否自然、保留的比喻与判断是否仍有支撑。来源实际存在的差异按已确定方式表达。

写入前核对来源与目标是否有新改动，更新受影响内容。按约定写入合并目标，来源保留供回查；目标替换范围按本次授权执行。核对正式文件、标题、加粗、引文、图位、FIG 和实体图片引用。

发现原意或来源取舍问题时回到第一阶段修正，论述连接问题回第二阶段，局部表达在成稿中调整，并同步相关产物。

完成条件：重要来源内容及真实差异得到合适处理，全文连贯且保持本次表达倾向，正式目标和引用正确。第三阶段记录交付位置、重要取舍与实际检查结果，运行 `--through 3` 后交付。用户要求 HTML／PDF 时，再进入入口的打印与导出。
