# 写作流程

首次完整读取本文件，按顺序执行三个阶段。每阶段使用有效产物和核心风格完成实际加工；达到该阶段内容条件、落盘并运行检查后，才进入下一阶段。恢复工作时可按目录补读当前所需的完整章节。

前期产物沉淀实际判断、解释、原句取舍、主线和关键衔接，完整文章在第三阶段形成。原始材料作为依据按需读取，产物保存已加工的内容。

发现依据或原意问题，修正第一阶段；论述和衔接问题，修正第二阶段；局部表达问题在第三阶段修订。更新受影响的产物及配图提示词，重跑当前检查点。

## 第一阶段：整理原意，确定文章怎样展开

使用本次任务记录和来源材料，应用核心风格中的原意、依据与表达要求。

### 工作与产物

读懂输入中用户的主张、理由、观察、例子和认识变化。核对影响文章的事实，分清模型补充与作者意思。选出值得保留的原句、比喻和判断，明确本篇叙述视角和力度。

把文章由来与主线写具体：从哪件事或概括性的观察进入，准备说清什么，各部分怎样承接。关键关系已经能解释时就实际写出来，早期风格要求落实到对象、概念、因果、语气和段落。

新写围绕输入形成主线；修改读到足够判断影响的原文范围，记录新增内容的自然归属和必要连带调整；合并读取指定来源，处理重复、主张差异和顺序。整体重组时完整阅读目标，局部修改按依赖范围补读。

当前产物保存实际整理后的意思、依据、表达取舍和内容关系，不以原始聊天或文章副本代替加工。前期内容可以简短，但应让后续清楚本篇真正要说什么。

### 可以继续时

作者原意与主要态度可辨认，重要内容有归属；主线对应实际材料；需要保留的表达已记录；关键事实与推断边界清楚。会改变主张的歧义、无法解决的来源冲突或明显超出授权的改动，具体询问后再继续。

落盘并按下方“产物与检查”运行 `--through 1`。内容条件成立且检查通过后，进入第二阶段。

## 第二阶段：沿主线写清关键论述

使用第一阶段的有效内容、本次要求和实际依据，应用核心风格。准备配图时读取入口列出的“配图与 FIG”。

### 工作与产物

沿已确定主线，把必要概念、原因、机制、观察、例子和判断写成实际可用的论述。解释一个关系需要前提时，补到读者能够理解当前意思的位置。紧密相关的内容连续写成自然段，独立部分可以分别准备，同时写出关键接续。

让本次适用的文风进入实际段落：平实叙述怎样铺开，判断在哪里落下，比喻对应什么，模拟话语是否帮助理解，哪些原句和加粗值得保留。自省文章沿认识变化展开，批判文章按本次表达保持力度。

拟定适合正文的标题和小标题，按实际需要准备图位、生图提示词及 FIG。提示词放在独立任务产物 `illustrations.md`，在当前阶段记录路径和与论述的对应；图注同时形成可进入正文的文字。正文与图注的锋芒或留白按同一篇文章判断。

产物由实际内容决定，可以是连续的大段论述、关键段落或相互关联的内容片段。简单文章可以接近全文，复杂文章先完成关键内容和连接；不为固定栏目把一条思路切成独立答案。

修改任务形成受影响部分的论述及衔接；合并任务使用已处理的来源关系，把互补内容写通。发现原意或事实问题，修正第一阶段并重跑当前检查点。

### 可以继续时

关键论述已经可用，必要概念和理由能被理解，各部分能够支撑同一主线；取舍和语气符合输入，重要转折有实际表达；本次需要的配图提示词与 FIG 已准备。无需为进入下一步强求完整初稿。

落盘后运行 `--through 2`。完成内容核对与结构检查后，进入第三阶段。

## 第三阶段：形成全文，核对修订并交付

使用前两阶段的最新内容、主线、本次要求及适用的图位和图注，应用核心风格。

### 形成完整文章并连续通读

将准备好的内容自然写成全文，完成引子、段落衔接、重复取舍和整体节奏。原有表达按实际语境保留或整合，不能只去掉编号后顺序粘贴材料。

完整初稿在本阶段产生，随后立即对照原意与风格检查并修订：主张、理由、例子和表达力度是否保留；个人经历是否确有输入依据；概念在使用时是否够用；事实及引文有无失真；段落能否顺着读；标题、加粗、比喻和短句是否服务内容；结尾是否落到本篇实际意思。

图注与图位核对实际段落，生图指令留在提示词文件。已有图片使用真实相对路径；待生成图片按配图指导保留图位注释与 FIG，不创建虚假的图片链接。

局部表达就地修订；原意、依据或关键论述改变时更新对应前阶段和提示词。新写形成完整文档，维护按授权范围更新，合并写入指定目标并保留来源。

### 写入与交付

写入前核对源文档和正式目标是否有更新，将新增变化纳入当前处理。目标路径和替换范围按准备阶段约定；保留无关修改。正文使用 Markdown，工作标记留在任务产物中。

核对实际文件、差异、图位、FIG 和链接；完整稿可保存在任务目录供回查，第三阶段区块记录成稿路径、重要变化与实际检查状态。需要恢复全文时实际读取该文件，不能用记录摘要代替正文。

完成条件：全文符合本次原意和适用风格，重要论述连贯，事实边界及图像状态清楚，正式文件已正确写入。运行 `--through 3` 后交付正文与提示词链接。用户要求 HTML／PDF 时，再读入口列出的“打印与导出”；仅导出不改变已经确定的主张和措辞。

## 产物与检查

任务目录在准备阶段确定，默认 `work.md` 保存任务说明和三个阶段产物。正文、提示词和导出文件位置按用户及项目约定执行。

### 标记与实际内容

每阶段内容包在独立行标记内，JSON 单行书写：

```markdown
<!-- essay:{"run":"article-1","stage":1} -->
本文围绕“完成与理解之间的差别”展开。开头沿用输入中真实提供的触发事件，
随后连接具体困惑与逐渐形成的认识；论述落到如何把理解留在过程中。
<!-- /essay -->
```

例子只示范格式，实际内容来自当前材料。`run` 标识本轮写作，`stage` 为 1–3；同轮同阶段只有一个有效区块，修订时就地更新。区块内按实际内容使用段落、列表、表格或代码。

前两阶段留下原意、依据、解释、内容关系和关键论述。第三阶段形成全文并核对修订，正文可以单独存入任务目录的草稿文件或正式目标；阶段区块记录真实文件路径和本次处理结果。后续需要全文时读取文件，不能把记录摘要当成正文。

配图提示词在任务目录的 `illustrations.md` 单独交付，第二阶段记录其路径与内容对应。需要时实际读取完整提示词和 FIG；阶段检查脚本不跟随外部文件，文件存在性、完整性及与正文的对应由 Agent 另外核对。

### 每阶段落盘后检查

使用本 Skill 内的 [check_artifacts.py](../scripts/check_artifacts.py)，以当前实际位置替换示意路径：

```sh
python3 "<Skill目录>/scripts/check_artifacts.py" \
  --task-dir "<任务目录>" --file "work.md" \
  --run "article-1" --through 2
```

`--through` 检查本轮第一阶段到当前阶段的标记与非空内容。每阶段完成实际工作、落盘并核对内容条件后都要运行，包括已有完整内容仍在上下文的情况。内容条件与结构检查都通过后，进入下一阶段。

- 返回 `0`：结构检查通过，仅报告这个含义。
- 返回 `1`：标记、缺阶段、重复或空区块有误，修正后重跑。
- 返回 `2` 或命令无法运行：核对参数、文件、路径和环境；无法解决时说明检查未完成及具体原因，不以口头声明替代。

脚本只读指定 Markdown，排除只有标题、注释、分隔线或空代码块的内容，不按字数、标题或特定词语打分。它不判断作者原意、文风、事实、实际阅读及执行先后，也不代替对应阶段的完成条件。

### 复用、补读与修正

本阶段需要的内容完整、有效且在上下文中时直接使用；缺失、截断、压缩后只剩摘要或磁盘版本更新时，按需补读：

```sh
python3 "<Skill目录>/scripts/check_artifacts.py" \
  --task-dir "<任务目录>" --run "article-1" --read-stages 1 2
```

补读输出指定区块的完整正文，不输出其他轮次或阶段。任务记录、独立草稿和提示词文件按实际依赖另读。`--read-stages` 与 `--through` 不能在同一调用混用，读取成功也不能替代落盘检查。

修正原意、依据或论述时，更新受影响的阶段产物、正文及提示词，再检查当前有效进度。恢复时核对本次要求和来源变化。已有结果可以贡献有效材料，新一轮仍按本次要求分阶段落盘，不用旧的完成状态替代新工作。
