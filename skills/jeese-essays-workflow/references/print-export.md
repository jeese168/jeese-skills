# 沿用既有版式导出 HTML／PDF

用于用户要求“导出 PDF”“排版精修”或“做成可打印 HTML”。Markdown 是正文源，内部 [HTML 模板](../assets/print.html) 与 [CSS](../assets/print.css) 固定打印骨架和样式。导出不改变已认可的正文判断、语气和标题组织。

## 核对正文与资源

先按 [入口的准备与路径](../SKILL.md#准备与路径) 确定正文、HTML、PDF 和工作目录。本次只给一个路径就共用，不擅自再创建固定的 `HTML/`；项目或用户明确分别存放时按相应位置执行。

读取完整 Markdown，确认标题、分类、引言和实际图片。分类与引言已有时采用作者文字；确实缺少时依据原文补出简短、忠实的内容，并同步 Markdown，不另造经历或改变正文。标题层级跟随原文。

本 Skill 只交付生图提示词。若当前正文有待配图位置，而用户要求 PDF，已有明确“先出无图稿”的要求就直接导出；否则一次问清先导出无图版还是等待图片。无图稿保留需要的文字和 FIG，移除不可渲染的图片引用，不假装已配图。用户提供图片后再接入真实文件。

## 转换为正文 HTML 片段

Agent 将 Markdown 转成正文语义 HTML，保留每段文字、强调、标题、链接、列表和图注。较长文章按段落核对来源与转换结果，确认没有丢失或重复内容。转换片段、元数据放在任务目录供检查。

- 篇名、分类与引言进入元数据；正文片段从其后的实际内容开始。
- `##` 映射为 `h2`、`###` 为 `h3`，没有大部就直接使用节级标题。
- 普通段落用 `p`，少数独立而重要的判断可用 `p class="pull"`；文内加粗为 `strong`。
- 首段确需首字下沉时用 `p class="lead"`，这是版面选择，不改变文字。
- 真实引文用对应语义标签，链接保留实际目标；公式需要时采用可打印的 MathML 或已有的可靠公式渲染结果，逐项核对含义与显示效果。

图的结构：

```html
<figure class="figure">
  <img src="文档图片/实际文件名.png" alt="图中实际对象和场景">
  <figcaption><span class="fig-label">FIG.</span>与 Markdown 完全相同的图注正文。</figcaption>
</figure>
```

较宽构图可以用 `figure figure-wide`。提示词留在任务文件，不进入正文片段；图片不存在时不创建 `img`。仅调整图注就改文字，仅调整图片就改实际引用。

元数据 JSON 只含三个非空字符串：

```json
{"title":"篇名","category":"随笔 · 本篇主题","intro":"作者原有或依据正文形成的简短引言。"}
```

用 [assemble_html.py](../scripts/assemble_html.py) 组合模板：

```sh
python3 "<Skill目录>/scripts/assemble_html.py" \
  --content "<任务目录>/body.html" --metadata "<任务目录>/metadata.json" \
  --source-dir "<Markdown所在目录>" --output "<HTML目标文件>"
```

片段中的图片和本地链接以 Markdown 所在目录为基准。脚本检查本地图片存在性与 alt，按 HTML 目标位置重新计算路径，对空格和中文编码，并转义元数据。脚本不自动解析 Markdown，也不改写文章；转换忠实性由 Agent 对照来源核对。明确更新既有目标时加 `--overwrite`。

## 固定的纸面与样式

模板和 CSS 提取自用户认可的《防御与回应》打印样板与项目排版约定，只保存样式与结构，不保留原文或本机路径。

模板内的 `table.print-shell`、`thead` 和 `running-head` 生成重复页眉，左边篇名、右边栏目。`html` 和 `body` 的 margin/padding 为 0，左右留白只来自 `@page`。标题区依次为分类、篇名、引言和细线。

| 部位 | 采用的样式 |
| --- | --- |
| 纸面 | A4；上 9mm、左右 20mm、下 16mm |
| 页眉到正文 | `thead` 单元格底部间距 8mm |
| 第一页页眉到刊头 | `.article-head` 顶部间距 6mm |
| 字体 | 正文、标题、引言和图注使用 Noto Serif CJK SC / Source Han Serif SC；页眉、分类和 FIG 小标使用对应 Sans 字族 |
| 正文 | 11.15pt，行距 1.80，段后 11.5pt，两端对齐 |
| 主标题 | 28pt，行距 1.22，字距 -0.025em |
| 引言 | 10.45pt，行距 1.48，宽 82%，与标题间距 15pt |
| 部／节标题 | h2 为 17pt，h3 为 14.7pt；首次紧接标题区的标题按模板消除额外间距 |
| 独立强调段 | `p.pull` 宽 82%，12.6pt，行距 1.58，细左边线 |
| 图片与图注 | 图宽 82%，宽图 87%；图注 8.55pt，FIG 小标 7.2pt |

色彩沿用 CSS 中的暖灰棕：白纸，正文近黑偏暖，页眉和图注较浅。细线、字号、字距、图片间距和首字样式以内部 CSS 为准，不在转换过程中重新设计一套皮肤。检查实际字体可用性；发生明显替代时说明差异并处理，不默认为已保持相同排版。

三种距离分别控制：纸顶到页眉改 `@page` 顶边距，页眉到正文改 `thead` 间距，第一页标题区改 `.article-head`。用户要求微调时只改对应变量，保留其他已认可样式；原有多项明确要求可以一并完成。临时版面微调作用于本次生成 HTML，修改 Skill 模板需用户明确要求。

## 浏览器打印

使用 [export_pdf.py](../scripts/export_pdf.py) 调用现有 Edge、Chrome 或 Chromium，路径可显式传入：

```sh
python3 "<Skill目录>/scripts/export_pdf.py" \
  --html "<HTML目标文件>" --output "<PDF目标文件>"
```

更新已授权目标加 `--overwrite`，浏览器未自动找到时用 `--browser "<现有浏览器可执行文件>"`。脚本使用临时浏览器配置，实际打印参数保持为：

```text
--headless=new
--disable-gpu
--no-first-run
--no-default-browser-check
--allow-file-access-from-files
--no-pdf-header-footer
--virtual-time-budget=20000
--user-data-dir=<临时配置目录>
--print-to-pdf=<临时PDF目标>
file://<实际HTML路径>
```

脚本正确构造本地 URI，打印成功后替换目标 PDF。`--allow-file-access-from-files` 用于本地图片，`--no-pdf-header-footer` 关闭浏览器日期与文件地址，设计页眉仍由 `thead` 提供。运行浏览器和写入目标服从平台权限；缺少浏览器或字体时说明实际缺口，不自行安装。

部分浏览器版本打印完成后仍保持进程，脚本在超时结束本次进程后，只保留有 PDF 文件头和完整结束标记的打印结果，并提示继续核对页面。未得到完整输出或浏览器实际报错时，保持已有 PDF 不变。文件完整性检查仍不代表版面检查通过。

用户说“只改、不渲染”时修改对应 HTML/CSS 后交付；要求导出时再打印。按可用平台能力打开或预览实际结果，并提供链接。

## 检查实际结果

HTML 生成成功和 PDF 文件存在都不代表版面检查完成。用可用 PDF 渲染工具把页面转成图片，查看首页及后续所有页面：字体是否可读，页眉是否重复，三种间距是否正确，标题是否孤立，图、FIG 和强调段是否被不合适地切断，有无溢出、空白页或缺图。再用文本提取辅助核对正文、标题和图注完整性。

发现排版问题，修正本次 HTML 后重新导出并看实际结果；本文字号、纸面和字体的整体调整由用户决定，不为了减少页数擅自缩字。没有预览能力时如实说明尚未视觉核对。导出记录保存在任务目录，不伪造成三个写作阶段都重新执行过。
